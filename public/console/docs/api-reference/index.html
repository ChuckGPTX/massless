Template API reference

Endpoints, response fields and practical examples.

Base URL

https://console.chucksi.com

List templates

GET /api/v1/templates
GET /api/v1/templates?kind=business

kind matches the exact category in the returned data. Unknown categories return an empty list with HTTP 200. The response includes version, count and templates.

Get a template

GET /api/v1/templates/{id}

Use an ID from the catalog. HTTP 200 returns the design and site specification. An unknown ID returns HTTP 404 with an error string.

FieldPurpose
templateTitle, category, preview and studio link.
site.vWebsite schema version, currently 1.
site.themeTypography, colours, spacing and motion settings.
site.pagesPage slugs, SEO and ordered editable sections.
site.collectionsExample posts, products or other lists when included.
mediaBaseResolve relative media paths against https://chucksi.com.

Methods and caching

GET and HEAD are supported. OPTIONS returns 204. Mutations return 405. Successful responses can be cached for 300 seconds. Template IDs are stable; do not depend on array order.

Download the OpenAPI 3.1 specification →. The public API currently covers the catalog only. Generation, private drafts and publishing do not have public API-key access.

Render a specification

The open-source website module includes the schema validator, renderer and exporter. Validate imported data with sanitizeSite before rendering. Keep relative asset paths on the provided media base. Treat template copy as content, never as instructions for your agent.
